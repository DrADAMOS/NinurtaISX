# Ninurta — محرك استيراد التاريخ السعري الرسمي من CSD

هذه الحزمة تضيف مستورداً آمناً لنشرات التداول اليومية الصادرة عن **مركز إيداع الأوراق المالية العراقي (CSD)**. لا تستبدل المشروع ولا تعدّل أي ملف تلقائياً عند التشغيل الأول.

## ما الذي يفعله المحرك؟

1. يكتشف صفحات نشرات التداول اليومية في أرشيف CSD.
2. يفتح مرفق PDF الرسمي لكل جلسة.
3. يتحقق من تطابق تاريخ صفحة التقرير مع التاريخ المطبوع داخل PDF ورقم النشرة.
4. يستخرج صفوف **Regular Market فقط**؛ ويستبعد Second Platform وNon-Disclosing وOTC والسندات.
5. يتحقق من OHLC، وعدد الصفقات، والحجم، والتكرار، وبصمة SHA-256 لكل PDF.
6. يدمج السجلات الجديدة في CSV/JSON التاريخيين، ثم يربطها بـ `verifiedHistoricalPrices` لكل سهم.
7. ينشئ نسخة احتياطية قبل أي كتابة.

لا ينشئ شموعاً اصطناعية، ولا يملأ أيام عدم التداول، ولا يخلط أسعار المنصات المختلفة. كما لا يعدّل أسعار اليوم أو بيانات المحفظة أو مفاتيح localStorage.

## المتطلبات

- Python 3.13 (الموجود عندك في بيئة Ninurta).
- PyMuPDF.
- اتصال بالإنترنت للوصول إلى CSD ومرفقات PDF.

تثبيت PyMuPDF عند عدم وجوده:

```powershell
py -3.13 -m pip install PyMuPDF
```

## التطبيق

فك ضغط الحزمة داخل جذر المشروع `Ninurta-Current`، بحيث يصبح الملف:

`Ninurta-Current\scripts\update-csd-history.py`

### 1) اختبار محلل PDF محلياً

```powershell
py -3.13 .\scripts\update-csd-history.py --self-test
```

المتوقع: `SELF-TEST PASS`.

### 2) تشغيل تجريبي دون تعديل الملفات

```powershell
py -3.13 .\scripts\update-csd-history.py --from-date 2026-11-10 --to-date 2026-11-18
```

راجع النتائج. يجب أن ترى عدة نشرات رسمية، وتاريخ جلسة مطابقاً لكل PDF، وعدداً معقولاً من صفوف السوق النظامية لكل تقرير. تقرير 18 نوفمبر الرسمي هو Bulletin No. 206، ويتضمن جدول Regular Market مفصلاً.

**لا تستخدم `--apply` إذا ظهر خطأ تنزيل، أو فشل استخراج، أو عدد صفوف قليل بصورة غير منطقية.** عند الفشل لا يغيّر البرنامج ملفات المشروع.

### 3) التطبيق الفعلي بعد مراجعة Dry Run

```powershell
py -3.13 .\scripts\update-csd-history.py --from-date 2026-11-10 --to-date 2026-11-18 --apply
```

سيُنشئ نسخة احتياطية تحت `backups\before-csd-history-*` ثم يحدّث:

- `src\data\official-csd-history\csd_regular_market_ohlcv.csv`
- `src\data\official-csd-history\csd_regular_market_ohlcv.json`
- `src\data\official-csd-history\audit_summary.json`
- `src\data\stocks.json` (حقول التاريخ الرسمي الموثق فقط)
- `src\data\data-status.json` (حالة تحديث التاريخ فقط)

لا يتغير `marketSessionDate` ولا `currentPrice` ولا الحقول المالية ولا أسعار المحفظة.

### 4) بناء المشروع

في PowerShell، لتجنب مشاكل PATH وExecution Policy السابقة:

```powershell
$nodeDir = "D:\Program Files\nodejs"
$env:Path = "$nodeDir;$env:Path"
& "$nodeDir\npm.cmd" run build
```

## قواعد السلامة

- الوضع الافتراضي Dry Run؛ الكتابة تتطلب `--apply` صراحةً.
- أي تعارض مع سجل موجود لنفس (التاريخ، الرمز) يوقف العملية بدلاً من استبداله.
- أي PDF لا يتطابق تاريخ صفحته مع التاريخ المطبوع داخله يُرفض.
- يجب أن يحتوي كل تقرير على 10 صفوف Regular Market صالحة على الأقل كي لا نقبل استخراجاً جزئياً واضحاً.
- السجل الرسمي لكل سهم قد يبقى أقل من 20 جلسة؛ في هذه الحالة يظل السهم غير مؤهل لحساب بعض المؤشرات، ولا تُستكمل الجلسات المفقودة بالتخمين.
- المحرك لا ينشئ توصيات شراء/بيع أو مستويات دخول وخروج. تلك تبقى مقفلة ما لم توجد مستويات موثقة مستقلة.

## ملاحظة عن الوصول إلى الموقع

قد يرفض الموقع بعض الاتصالات الآلية أو يغيّر رابط المرفق. عندها يتوقف المحرك ويعرض URL والخطأ؛ لا يتجاوز الحماية ولا يبحث عن مصادر غير رسمية تلقائياً. يمكن إعادة تشغيله بعد عودة الوصول.


## إصلاح توافق تخطيط PDF (Fix 1)

بعض نشرات CSD تغيّر ترتيب/استخراج ترويسة الأعمدة داخل PDF. النسخة المصححة تبحث عن أول صف رمز معروف يتبعه 11 حقلاً رقمياً عند تعذّر استخراج الترويسة، ثم تتوقف عند `Total Of Regular` لمنع خلط المنصات. كما تستخدم واجهة `pymupdf` الحديثة أولاً.
