# Ninurta ISX Pro — Phase 6

## التحسينات
- يحاول التطبيق استخراج النص الأصلي من PDF أولاً.
- إذا لم ينتج استخراج النص حركات قابلة للتعرّف، ينتقل تلقائياً إلى OCR العربي والإنجليزي.
- يبقى OCR محمّلاً عند الحاجة فقط، وليس عند فتح التطبيق أو استيراد CSV/Excel.
- معالجة صفحات PDF بالتتابع لتقليل استهلاك الذاكرة، مع تحرير موارد الصفحة والـ PDF بعد الانتهاء.
- إضافة اختبارات لترتيب وتجميع أسطر PDF، مع الحفاظ على تغييرات Phase 5 للتحميل الكسول للنوافذ.
- لا تُحفظ أي حركة مستخرجة تلقائياً؛ يجب مراجعتها واعتمادها يدوياً كما في الإصدار السابق.

## طريقة التطبيق
1. فك ضغط `Ninurta-Phase6-PDF-OCR-Optimization.zip` مباشرة داخل مجلد `Ninurta-Current`.
2. افتح PowerShell داخل مجلد المشروع.
3. نفّذ الأمر:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\phase6patch\Apply-Phase6-PDF-OCR-Optimization.ps1"
```

السكربت يحفظ نسخة احتياطية، يطبق الملفات، ثم يشغّل الاختبارات وTypeScript والبناء. إذا فشلت خطوة تحقق، يعيد الملفات التي عدّلها إلى النسخة السابقة.

> ملاحظة: إذا كان الملف PDF نصياً، قد تظهر الحركات المستخرجة أسرع لأن OCR لن يعمل. إذا كان PDF ممسوحاً ضوئياً، سيستمر استخدام OCR كمسار احتياطي. دقة OCR واتجاه المدين والدائن تتطلبان مراجعة المستخدم دائماً.


إصلاح إضافي: تمت معالجة خطأ TypeScript في نوع عناصر PDF.js داخل AccountStatementView.tsx باستخدام type guard آمن يبدأ من unknown ويتحقق من str و transform قبل تمرير العناصر إلى تجميع النص.
